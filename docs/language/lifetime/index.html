VOID Language lifetime & abstractions

Structured cleanup.
Synchronous or async.

VOID treats resource cleanup as control flow, not a separate runtime feature. IDisposable, IAsyncDisposable, using, await using, iterator disposal, async iterator disposal, exceptions, and finally all build on the same cleanup model.

Completed lifetime & abstraction foundation

Cleanup keeps one set of rules across suspension.

Synchronous disposal and async disposal both lower through VOID's structured cleanup machinery. A resource may leave scope normally, through an exception, or after an await, but cleanup ordering and lifetime rules still come from the same control-flow model.

Structured lock release

lock uses the same structured-finally transfer stack as exceptions and deterministic disposal, so monitor release is not skipped by normal fallthrough, return, break, continue, or managed exceptions.

IDisposable & iterator disposal

Void.IDisposable is part of the root library contract. Collection enumerators and compiler-generated iterators can dispose deterministically, including pending iterator cleanup.

Foreach disposal

Non-array foreach disposes its enumerator on normal completion, early break, return, and exception paths through structured cleanup.

Using statements

C#-style using (...) works with disposable reference and value types, null resources, nesting, exceptions, and normal GC behavior.

Using declarations

using var and typed using declarations dispose resources at scope exit in reverse declaration order across normal and exceptional exits.

IAsyncDisposable & await using

Task-based asynchronous disposal uses the same structured cleanup graph as finally. await using preserves cleanup ordering, faults, cancellation, and managed lifetime even when disposal itself suspends.

Async iterator cleanup

await foreach and compiler-generated async iterators retain their enumerator and producer state across suspension, then dispose asynchronously on normal completion, early exit, faults, cancellation, or consumer teardown.

Generic method inference and conversion provenance

Generic calls can omit explicit type arguments when VOID can infer them through the existing overload resolver and monomorphizer, including constrained and by-reference cases where inference is well-defined.

Extension methods

Static methods with a this first parameter can participate in instance-style call syntax while preserving ordinary instance-member precedence and normal overload resolution.

Static interface methods

Interfaces can require static methods as compile-time contracts, implemented by ordinary public static methods on concrete classes or structs without interface-owned static storage.

Constrained static dispatch

Generic code constrained by an interface can call required static members through the type parameter; monomorphization lowers the call to the concrete static implementation.

Default interface methods

Interface methods may provide bodies. Concrete implementations take precedence, inherited defaults provide fallback behavior, and ambiguous inherited defaults are diagnosed.

One cleanup model

using and await using share the same foundation.

Structured exits, rethrow, GC-safe unwinding, iterator cleanup, and async suspension all feed the same cleanup control flow. Synchronous and asynchronous disposal therefore differ in whether cleanup can suspend, not in whether a second lifetime system takes over.

Deterministic disposal
public sealed class GameFile : IDisposable
{
    public void Dispose()
    {
        Console.WriteLine("closed");
    }
}

using (GameFile file = new GameFile())
{
    Run(file);
}
Generic inference + extension method
public static T Identity<T>(T value)
{
    return value;
}

public static int Twice(this int value)
{
    return value * 2;
}

int value = Identity(21);
Console.WriteLine(value.Twice() == 42);
Asynchronous disposal
public sealed class AsyncResource : IAsyncDisposable
{
    public async Task DisposeAsync()
    {
        await Task.Run(() => Console.WriteLine("closed"));
    }
}

public static async Task RunAsync()
{
    await using (AsyncResource resource = new AsyncResource())
    {
        await UseAsync(resource);
    }
}
Constrained static + default interface behavior
public interface IFactory<T>
{
    static T Create();

    string Name()
    {
        return "default";
    }
}

public static T Build<T, TFactory>()
    where TFactory : IFactory<T>
{
    return TFactory.Create();
}

Iterator lifetime

Pattern-captured iterator values follow the same lifetime rules.

Pattern locals and managed intermediate values that survive yield are promoted into normal iterator state-machine storage, remain rooted through suspension and forced GC, and participate in disposal, exception, finally, and teardown cleanup without a parallel capture system.
