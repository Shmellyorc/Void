Language + runtime

A complete language core.

VOID is meant to feel like a practical managed language for games, not a collection of isolated syntax features. Its object model, value semantics, cleanup, threading, GC, native boundary, and tooling are designed to share the same compiler and runtime rules.

Language & runtime

Features that compose into normal game code.

Features matter most when they survive real composition. VOID focuses on consistent behavior when generics, GC, exceptions, iterators, native calls, and concurrency meet in the same program instead of treating each feature as its own island.

Object model & generics

Current Classes, nested/readonly structs, inheritance, constructor chaining/delegation, interface inheritance, struct interface implementation/boxing, static interface property/event contracts, virtual/abstract/override properties, generic types/methods with class/struct/base/interface/new() constraints, explicit generic calls through arbitrary receivers, delegates, nested/by-reference closures, custom and field-like events, attributes, and runtime discovery.

Collections & iteration

Current Single-dimensional, jagged, and rectangular arrays with inferred rectangular initializer shapes; List<T>, Queue<T>, Stack<T>, Dictionary<TKey,TValue>, HashSet<T>; foreach, enumerators, and iterator state machines with ordinary inferred/definitely-assigned/shadowed locals.

Value-type semantics

Current Nested value structs, readonly struct, readonly instance methods/accessors, calls through in, value copying/defaults, generic/nullable/static value layouts, and recursive GC tracing through managed references inside nested structs.

Closure & iterator completion

Current Nested lambdas, per-iteration foreach capture frames, ref/out/in captures and lambda parameters, struct this capture, and iterator state across foreach, switch, nested loops, base-member access, and suspension.

Compound assignment targets

Current Compound assignment through indexers and writable vector swizzles preserves single evaluation of receivers, indices, and right-hand sides.

Nullable value types

Current Native non-boxed T? storage, HasValue/Value, nullable fields/properties/arrays/generics, nullable enums/structs, and GC tracing through nullable structures containing managed references.

Nullable operators

Current Lifted arithmetic/comparisons, ??, ??=, value-returning ?., and null-conditional indexing with ?[].

Conversion semantics & generic conversions

Current One semantic conversion engine classifies standard conversions, resolves user-defined implicit/explicit conversions, lifts through nullable values, serves target-typed sites, validates static-interface conversion contracts, and authorizes constrained generic implicit/explicit dispatch with provenance preserved through specialization, iterators, closures, and GC.

Named arguments & defaults

Current Named argument reordering, optional/default parameters, params, default(T), and target-typed default across locals, returns, arguments, fields, properties, generics, enums, pointers, structs, and nullable values.

Instance & object initialization

Current Instance field and auto-property initializers run before constructor bodies, while object initializers apply normal accessible field/property assignments after one construction.

Array & collection initializers

Current Inline arrays and collection initializer syntax through ordinary Add(...) binding, including generic collections, conversions, nullable values, and managed references.

Static members & type initialization

Current Static fields/properties, static readonly, static constructors, before-first-use run-once initialization, base-before-derived ordering, generic static state, and GC roots for managed static references.

Core ergonomics

Current Enums, switch, const/readonly, casts, is/as, null operators, optional parameters, typeof, runtime type metadata, and user-defined implicit/explicit conversions.

Control & member surface completion

Current Post-test do/while loops, expression-bodied methods/constructors/operators/conversions/setters, and custom event add/remove accessors all lower through the same existing semantic and code-generation paths.

Exceptions & runtime control flow

Current Managed Exception types, throw, typed and catch-all catch, cross-call propagation, GC-safe unwinding, finally, structured return/break/continue through cleanup, nested handlers, bare rethrow, iterator/delegate/event integration, native/library boundaries, and static-initializer recovery now compose through one runtime-control-flow model.

Managed threading, Tasks & synchronization

Complete Concurrency is part of the managed runtime rather than a detached native layer. Direct threads and ThreadPool workers participate in GC coordination, while Tasks reuse the same waits, faults, cancellation, synchronization, closures, generics, and native-boundary rules. Interlocked and Volatile keep atomic access and publication inside that same model.

Async Task methods & state machines

Current async methods returning Task or Task<T> lower into compiler-generated state machines over the existing Task runtime. Suspension and resumption, typed results, multiple sequential awaits, exceptions and finally, cancellation, generics, closures, GC lifetime, object-model dispatch, and library boundaries already share normal VOID semantics. The active roadmap generalizes await expression positions and adds asynchronous disposal, enumeration, and iterators.

Array surface completion

Current Null-conditional indexing works across single-dimensional, jagged, and rectangular arrays. Rectangular initializers support explicit compile-time dimensions as well as new[,]-style inferred dimensions while preserving shape validation, conversions, row-major evaluation, and GC safety.

Conditional expressions

Current Target-typed ?: expressions compose with interface/reference values, structs through interface targets, delegates, nullable values, user conversions, generics, and single-evaluation semantics.

Reusable library projects

Current Projects can emit native static archives, export public static VOID methods with stable C symbols, preserve static initialization/GC roots across repeated calls, and be consumed from VOID or plain C through the existing native ABI.

Receiver & generic call completion

Current Instance methods can be called through constructor/method/property/indexer/array/conditional/temporary receivers with single evaluation and GC safety. Explicit generic calls work through static, instance, inherited, virtual, interface, specialized-generic, and temporary receiver paths.

Deterministic lifetime & using

Complete IDisposable, generated iterator disposal, non-array foreach cleanup, using (...), and using var share the same structured cleanup machinery used by finally, including early exits and exceptions.

Inference, extensions & interface abstractions

Complete Generic method type inference, extension methods, static interface method contracts, constrained static calls through type parameters, and default interface methods reuse the existing overload, monomorphization, and interface-dispatch systems.

Pattern matching & switch expressions

Complete Declaration/type, constant/null, relational, logical, property, and recursive patterns compose with flow-aware locals, deterministic pattern-switch ordering, when guards, and target-typed switch expressions.

Operators & constrained generic math

Complete User-defined unary and binary operators use normal overload/conversion resolution, static interfaces can require operators, and constrained generic code dispatches those operators through monomorphized concrete implementations. Iterator lowering preserves generic constraint provenance across yield.

Managed runtime

Current Garbage collection traces managed references across objects, inheritance, interfaces, nullable structures, collections, iterators, delegates, closures, events, static roots, and every registered managed thread. Cooperative safepoints and native-quiescent states coordinate stop-the-world collection without losing worker roots.

Unsafe & native interop

Current Pointers, unsafe delegates with pointer and by-reference pointer signatures, pointer properties across unsafe classes/interfaces/value types, pointer constructors, native structs, native ref/out/in, callbacks, aliases, local native dependencies, reusable VOID static-library output with exported C symbols, sizeof, memory copy/clear, and stackalloc.

Compiler tooling

The tooling block is complete.

Source spans and ranged diagnostics feed both voidc check and voidc lsp. The semantic query layer powers hover, signature help, completion, go-to-definition, references, and document/workspace symbols. Live diagnostics analyze unsaved buffers, UTF-8 compiler positions are converted to LSP UTF-16 coordinates, and multi-file editor sessions are analyzed as one in-memory project snapshot so dependent files do not see stale disk state.
