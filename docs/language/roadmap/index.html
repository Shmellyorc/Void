VOID Language roadmap

Timed synchronization is complete.
Now build ThreadPool & Tasks.

Monotonic timing, Thread.Sleep, timed monitor waits, reset events, semaphores, and cooperative cancellation are complete. The active phase builds the reusable scheduler and task-completion model that future async/await lowering can target without compiler-only runtime magic.

Current phase

ThreadPool & Task Foundation

Current

Tasks will use the ordinary VOID threading, synchronization, GC, exception, timeout, and cancellation infrastructure. This block adds one reusable worker pool plus Task/Task<T> completion, scheduling, waiting, cancellation, continuations, and completion sources. Full async/await syntax remains a later lowering phase.

Next

Managed ThreadPool & work queue foundation

Establish a reusable FIFO work queue and persistent managed workers on top of the existing Thread, Monitor, atomics, and wait primitives. Add the initial ThreadPool queue surface without introducing a second native threading backend.

Planned

ThreadPool worker lifecycle & GC coordination

Complete worker startup, sleeping/wakeup, delegate rooting, queue-node lifetime, stop-the-world GC interaction, nested allocation, and safe idle workers so pool workers behave exactly like existing managed threads.

Planned

ThreadPool exception, shutdown & stress completion

Define queued-work exception behavior, preserve worker survival and cleanup where appropriate, complete deterministic pool shutdown, and stress concurrent producers and workers before Tasks depend on the scheduler.

Planned

Task state & completion foundation

Introduce the non-generic Task completion object with synchronized pending, running, completed, faulted, and canceled states, exactly-once completion, and safe observation without adding async methods yet.

Planned

Generic Task<T> result & GC completion

Add typed value/reference results, result rooting, exception storage, generic specialization, and lifetime correctness while reusing the same task state machinery instead of creating a parallel generic implementation.

Planned

Task.Run & ThreadPool scheduling integration

Connect Action and Func<T> work to the pool, covering closures, delegates, generic work, nested tasks, worker-to-worker scheduling, and managed/native execution boundaries.

Planned

Task waiting, timeout & fault propagation

Add synchronous task waiting/result observation through the completed timed-synchronization layer and preserve original task faults through VOID's existing exception system.

Planned

Task cancellation integration

Integrate CancellationToken with queued and executing task state so cancellation races safely with scheduling, start, completion, faults, timeout, and disposal without pretending arbitrary running code can be forcibly terminated.

Planned

Task continuation & completion-source foundation

Add race-safe completion continuation registration plus a TaskCompletionSource-style mechanism for completing, faulting, or canceling tasks, including continuation GC lifetime, immediate registration after completion, nesting, and generic results.

Planned

ThreadPool & Task integration audit

Audit the scheduler, Task, Task<T>, cancellation, timeouts, faults, continuations, closures/delegates, generics, GC, nested worker activity, native boundaries, and deterministic cleanup before asynchronous language lowering begins.

What changed

Timing and cancellation now sit underneath the scheduler.

VOID now has monotonic timed waits, managed sleep, reset events, semaphores, and cooperative cancellation on the same runtime foundation as threads, monitors, atomics, exceptions, cleanup, and GC. The next block can build ThreadPool and Tasks as ordinary managed abstractions, then let future async/await lowering target those mechanisms instead of inventing a separate scheduler or lifetime model.

A foundation, not a cage.
