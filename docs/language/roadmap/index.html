VOID Language roadmap

Async language integration is complete.
Now make references first-class.

General await expressions, async cleanup, await foreach, and async iterators now share the same Task, iterator, exception, GC, and cleanup architecture. The active phase builds a safe by-reference model that can connect managed arrays and structs to stack and native memory without turning ordinary ref code into raw-pointer programming.

Current phase

By-Reference Semantics & Span Foundations

Current

VOID already has ref/out/in parameters, arrays, structs, unsafe pointers, stackalloc, generics, native interop, and managed GC. This block gives those pieces one safe by-reference model: refs carry provenance and lifetime information, escape analysis protects stack-backed references, ref structs provide stack-only containers, and Span<T>/ReadOnlySpan<T> build on those rules instead of compiler magic.

Next

First-class ref locals

Add ref T local aliases over locals, parameters, fields, and array elements. The compiler tracks lvalue provenance, definite assignment, and the managed owner that must stay rooted when a ref points inside an object or array.

Planned

Ref assignment & aliasing

Complete target = ref source, chained aliases, mutation through aliases, struct-field refs, readonly checks, and control-flow lifetime while reusing VOID's existing write-target and by-reference argument machinery.

Planned

Ref returns

Add ref T method returns, return ref, and ref-returning calls as writable targets while rejecting references to dead locals, temporaries, and stack storage that cannot outlive the call.

Planned

Ref-returning properties & indexers

Extend the same by-reference semantics through properties and indexers with single evaluation, generic specialization, valid interface or virtual dispatch, readonly rules, and managed-owner retention.

Planned

ref readonly & escape scopes

Add readonly references plus formal escape-scope analysis for stack storage, parameters, managed interior references, and longer-lived storage. Introduce an explicit scoped surface only if the language needs it to express those rules clearly.

Planned

Ref struct foundation

Add stack-only ref struct values that may contain byrefs without silently escaping into the managed heap. Fields, constructors, methods, properties, and ordinary stack locals follow the same lifetime model.

Planned

Ref-like lifetime & suspension safety

Integrate ref-like values with generics, closures, delegates, exceptions, iterators, async methods, await, and yield. Unsafe capture or suspension paths are rejected unless the compiler can prove the lifetime is valid.

Planned

Span<T> & ReadOnlySpan<T>

Build spans as ordinary standard-library ref structs over the by-reference foundation, with length, indexed access, writable versus readonly behavior, and deliberate rules for native and managed element storage.

Planned

Span integration & ref foreach

Connect spans to arrays, stackalloc, valid unsafe pointer-backed views, slicing, managed-owner lifetime, and ref/ref readonly foreach so safe byrefs and the existing native-memory model meet cleanly.

Planned

By-reference & span integration audit

Audit refs, escape scopes, ref structs, spans, arrays, stack storage, generics, interfaces, native calls, closures, exceptions, GC, and diagnostics together. The block closes architectural gaps without pulling in unrelated ownership, SIMD, scheduler, or memory abstractions.

Why this comes next

Native performance needs a safe middle layer.

Async no longer exposes the largest architectural gap. VOID already has managed values on one side and explicit unsafe pointers on the other, but ordinary game code still lacks a first-class way to alias existing storage safely and efficiently. The next block builds that middle layer in order: tracked byrefs first, then escape rules, ref-like stack-only values, and finally spans as library types over those semantics.

A foundation, not a cage.
