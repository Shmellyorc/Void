VOID Language roadmap

Core Strings, UTF-8 & Text Construction

The managed string engine and native ABI boundary are complete. The next phase turns that representation into the everyday text model: valid UTF-8, Unicode-scalar char semantics, indexing and slicing, deterministic ordinal operations, efficient construction, and interpolation.

Current phase

Core Strings, UTF-8 & Text Construction

Current

VOID now has one managed, length-aware UTF-8 string type and explicit native string ABI contracts. This phase builds the ordinary text surface on top of that foundation while keeping Unicode-scalar positions distinct from raw UTF-8 byte counts.

Next

UTF-8 Validity & Unicode Scalar Foundation

Make valid UTF-8 an enforced managed-string invariant with one shared decoder/validator. Native-to-VOID construction rejects malformed text while preserving embedded NUL and valid Unicode scalar values.

Planned

String Core Properties & Empty Semantics

Add Length, ByteLength, IsEmpty, and string.Empty. Length counts Unicode scalar values while byte length remains directly available, and null stays distinct from the empty string.

Planned

String Character Indexing, Index & Enumeration

Make indexing and foreach (char ...) operate on Unicode scalar positions, including from-end Index forms. Normal string syntax never exposes partial UTF-8 code units.

Planned

String Range Slicing & Substring Completion

Add Range-based slicing and the normal Substring surface using the same scalar-index rules as character indexing. Slices return ordinary immutable managed strings rather than borrowed string views.

Planned

String Concatenation & Composition

Add string/char concatenation and += through length-aware UTF-8 construction. Size the result once with overflow checks instead of repeatedly rescanning text or falling back to C-string operations.

Planned

Ordinal String Search & Comparison

Add deterministic ordinal search, prefix/suffix tests, index lookup, and comparison. Implementations may optimize over UTF-8 bytes internally, but positions returned to VOID follow the scalar-index contract.

Planned

Immutable String Editing Operations

Add Insert, Remove, and Replace through the shared UTF-8/scalar helpers. Strings remain immutable, embedded NUL remains ordinary content, and no mutable alternate string type appears.

Planned

StringBuilder / Efficient Text Construction Foundation

Add mutable construction storage for repeated text building, likely under Void.Text. The builder is a utility, not another text type, and its output is always a normal managed string.

Planned

Interpolated Strings & Primitive Text Formatting

Add familiar interpolated-string syntax and lower it through the text-construction machinery. Primitive formatting is deterministic and invariant here; culture-specific formatting remains future work.

Planned

Core Strings, UTF-8 & Text Construction Integration Audit

Audit strings across GC, collections, generics, async state, threads, native ABI, exports, building, interpolation, and generated C. The final audit guards against raw C-string semantics, duplicate UTF-8 decoders, or a second ordinary text representation.

Managed Strings & Native String ABI

▾
  • Managed String Representation Foundation: Replace raw const char * storage with GC-managed VcString * carrying an explicit byte length. Literals use their compiled length so embedded NUL survives. Existing NUL-terminated extern calls keep working temporarily through a call-scoped borrow bridge without defining the permanent native string ABI.
  • Length-Aware String Semantics & Embedded-NUL Completion: Move equality, hashing, output, metadata, and related runtime paths to managed byte lengths instead of C termination rules. Embedded NUL remains ordinary string data, establishing VOID string semantics before permanent native ABI policy.
  • Native String ABI Contract Metadata Foundation: Keep string as the source-language type while native declarations carry metadata describing its ABI representation: borrowed NUL-terminated, pointer + length, borrowed/static return, owned return, or retained lifetime. Invalid combinations are diagnosed through VOID's existing native/attribute machinery.
  • Borrowed NUL-Terminated UTF-8 Parameter Completion: Define borrowed NUL-terminated UTF-8 parameters as call-scoped views over managed string data. Reject embedded NUL at this boundary, define null behavior explicitly, and avoid conversion or allocation when the managed value is already suitable.
  • Pointer + Length Native UTF-8 Parameters: Support pointer + length UTF-8 parameters so native APIs can receive the full managed byte sequence, including embedded NUL, without conversion. Borrow directly when possible and validate any native length conversion instead of silently truncating.
  • Borrowed & Static Native String Returns: Convert borrowed or static native UTF-8 returns, including pointer + length forms, into ordinary managed strings before VOID code receives them. Native pointers never escape as fake managed strings, and null native results have defined semantics.
  • Owned Native String Returns & Release Contracts: Handle native-owned string returns with explicit release contracts. Convert the text into a managed string, release native storage exactly once, and keep failure and exception cleanup safe from leaks or double release.
  • VOID String Export ABI: Let exported VOID APIs use normal string without exposing the internal VcString layout as the C ABI. Marshal inbound text into managed strings and outbound text into stable ABI representations with explicit lifetime and ownership rules.
  • Native String Lifetime, Callback & Boundary Integration Completion: Apply the string ABI contracts across callbacks, function pointers, threads, library boundaries, GC transitions, and exception cleanup. Retained pointers require explicit lifetime contracts, while writable native text buffers remain separate from immutable managed strings.
  • Managed Strings & Native String ABI Integration Audit: Audit managed strings and every native string boundary end to end: embedded NUL, GC/storage paths, parameter and return contracts, exports, callbacks, ownership, and generated C. Guard specifically against reintroducing string == const char * or inventing a second ordinary text type.

Async Timing & Cancellation Composition

▾
  • Shared Monotonic Timer Queue Foundation: Build one internal timer service on the already-locked monotonic timing/runtime primitives. It should support cancellable timer registrations and multiple deadlines without spawning one thread per timer and without putting a ThreadPool worker to sleep for the duration. This is infrastructure only; no Task.Delay yet. The timer service should be shared by every later feature in this block.
  • Task.Delay Foundation: Add Task.Delay(int millisecondsDelay). Zero completes immediately, finite delays use the shared timer queue, and Timeout.Infinite represents a Task that does not complete by time. Invalid values below -1 fail deterministically. Absolutely no Thread.Sleep, worker blocking, or thread-per-delay implementation.
  • Task.Delay Cancellation & Race Completion: Add Task.Delay(int millisecondsDelay, CancellationToken cancellationToken). Pre-cancellation, cancellation while pending, timer-vs-cancel races, originating token propagation, registration cleanup, GC rooting, and exactly-one terminal transition. A losing timer/cancellation callback must become harmless.
  • CancellationTokenSource Disposal & Registration Lifetime Completion: Make CancellationTokenSource properly disposable and give it deterministic ownership of external registrations/timer registrations. This is an architectural prerequisite for linked sources and delayed cancellation so they do not leave parent registrations or timer state rooted forever. Existing cancellation semantics stay intact.
  • CancellationTokenSource.CancelAfter Completion: Add delayed cancellation using the same timer queue: source.CancelAfter(millisecondsDelay); Support finite delay, zero, Timeout.Infinite disabling, repeated deadline replacement, ordinary Cancel() racing with the timer, disposal, forced GC, and concurrent reset/cancel races. Do not implement this as Task.Delay(...).ContinueWith(...).
  • Linked CancellationTokenSource Completion: Add linked-token composition, one/two-token and/or params forms as fits VOID's existing API conventions. Parent cancellation should cancel the linked source through ordinary cancellation registrations; no polling thread and no compiler support. Disposing the linked source must unregister from every parent deterministically.
  • Task.WaitAsync Cancellation Completion: Add nonblocking Task.WaitAsync(CancellationToken token) and Task<T>.WaitAsync(CancellationToken token). Cancellation applies to waiting for the Task, not to the original Task itself. If the wait is canceled, the antecedent keeps running and may complete later. Result/fault/cancellation from the antecedent propagate normally when it wins. Use Task continuations + cancellation registrations, not a blocked worker.
  • Task.WaitAsync Timeout & Combined Cancellation Completion: Add timeout forms, including the combined timeout/token form. A timeout should fault the proxy with a proper TimeoutException; cancellation should produce normal cancellation; antecedent completion should propagate its own state. Task-vs-timeout-vs-cancellation races must have exactly one winner and clean up both timer and token registration afterward. Again, the antecedent Task remains untouched if the wait times out or is canceled.
  • Async Timing, Cancellation, GC & Thread Integration: Cross-system integration milestone. Combine Task.Delay, CancelAfter, linked sources and WaitAsync with async lambdas, ValueTask/custom awaiters, await using, WhenAll/WhenAny, async iterators, exceptions/finally, forced GC, ThreadPool contention, static-library/native boundaries, and timer/cancellation races. High-iteration race stress stays opt-in outside make test.
  • Async Timing & Cancellation Integration Audit: Final architecture audit for the block. Recheck monotonic deadlines, timer ownership, shutdown/lifetime behavior, timer-vs-cancel races, cancellation registration cleanup, GC roots, Task result propagation, native POSIX/Windows timing paths, and all earlier async systems. This gets the mandatory complete cumulative make test.
Completed

Async Lambdas, Async Disposal & Task Composition

▾
  • Async Lambda Syntax & Semantic Foundation: Add async () => ..., async x => ..., and block-bodied async lambdas. Target Task/Task<T>/ValueTask/ValueTask<T>-returning delegates and reuse the existing async return/await semantic rules. I would deliberately not add async void yet; completion/faults should remain observable unless we later design a proper fire-and-forget error policy.
  • Async Lambda State-Machine Lowering: Lower async lambdas through the existing async state-machine machinery rather than creating a lambda-specific async engine. Completed and genuinely suspending awaits, multiple awaits, return values, faults, cancellation, and generalized custom awaiters all go through the mechanisms already locked by the existing async work.
  • Async Lambda Capture, Generic & GC Lifetime Completion: Make closure capture and suspension coexist correctly: captured locals, parameters, this, managed references, structs, generic values, nested lambdas, forced GC, and lambda/state-machine lifetime. This is important because an async lambda potentially has both a closure object and a suspension state machine.
  • Async Lambda Delegate, Event & ValueTask Integration: Exercise ordinary/generic delegates, Task and ValueTask delegate results, delegate invocation, events whose delegate returns an awaitable, interface/object-model interaction, library boundaries, custom awaitables inside async lambdas, and diagnostics. Still one async mechanism.
  • await using Syntax & Structural Async-Dispose Semantics: Add statement/declaration forms such as await using (...) and await using var .... Resolve DisposeAsync() structurally and run its result through the existing generalized awaiter binder, requiring GetResult(): void. The locked Task-returning IAsyncDisposable interface stays unchanged; Task, ValueTask, and custom valid awaitables should all work.
  • await using State-Machine & Structured Cleanup Completion: Complete asynchronous disposal through normal exit, return, break, continue, faults, catch/finally, nested resources, mixed synchronous/async using, LIFO cleanup, disposal suspension, disposal faults, and managed-resource GC lifetime. No separate cleanup state machine.
  • Task Completion Factories & Async Task.Run Unwrapping: Add the missing composition primitives such as CompletedTask, FromResult<T>, faulted/canceled task construction, and proper Task.Run(Func<Task>) / Task.Run<T>(Func<Task<T>>) behavior. An async delegate passed to Task.Run must produce one Task, not Task<Task>, and unwrapping must be continuation-driven rather than blocking a worker with Wait().
  • Task.WhenAll Completion: Add nonblocking Task and Task<T> aggregation, generic result arrays in original input order, empty-input behavior, GC rooting, cancellation/fault propagation, and races. I would fit this to VOID's existing singular Task exception model rather than bolt on a half-designed .NET AggregateException subsystem just for this milestone.
  • Task.WhenAny Completion: Add race-safe first-completion composition for Task and Task<T>. The outer Task completes successfully with the winning Task regardless of whether that winner completed, faulted, or canceled. Cover simultaneous completion, GC, async lambdas, await using, ValueTask/custom awaits, and worker-thread races.
  • Async Lambdas, Async Disposal & Task Composition Integration Audit: Final block-wide audit combining async lambdas, captures, generalized awaiters, Task/ValueTask, await using, Task.Run unwrapping, WhenAll/WhenAny, exceptions, cancellation, async iterators, GC, threads, native/library boundaries, and diagnostics. This is the milestone where I run the mandatory complete cumulative make test.
Completed

Generalized Awaitables & ValueTask Foundations

▾
  • Awaiter Protocol Semantic Foundation: Teach semantic analysis the structural await pattern: GetAwaiter(), IsCompleted, OnCompleted(Action), and GetResult(). No .NET interface dependency; VOID owns the contract. GetResult() determines whether the await expression is void or produces a value.
  • General Awaiter State-Machine Lowering: Extend the existing async state machine so arbitrary awaiters can suspend/resume. The awaitable must be evaluated once, the awaiter stored correctly across suspension, completion checked once, continuation registered through OnCompleted, and GetResult() executed after resumption. This should extend the current async machinery, not create a second lowering pipeline.
  • TaskAwaiter & Task Await De-Specialization: Add TaskAwaiter / TaskAwaiter<T> and Task.GetAwaiter(). Then move ordinary await Task onto the same generalized protocol as custom awaitables. After Task de-specialization, Task should no longer need a private compiler-only await path. I would also let the awaiter use Task's internal continuation registration directly instead of allocating an extra continuation Task.
  • Generic, Struct & Extension Awaiter Completion: Make the protocol compose with generic awaitables, generic awaiters, ordinary value-type awaiters, and existing extension-method resolution for GetAwaiter. Ref-like values that cannot legally survive suspension must be diagnosed rather than boxed or silently copied somewhere unsafe.
  • Task.Yield / Allocation-Free Yield Awaitable: Introduce a small YieldAwaitable/awaiter value type. IsCompleted is false, continuation registration queues through the existing ThreadPool, and GetResult() is empty. This gives VOID a real custom awaitable in its own standard library and proves generalized await works without manufacturing a Task object.
  • ValueTask Foundation: Add non-generic ValueTask as a true value-type awaitable. A synchronously completed value should require no Task allocation; an incomplete/faulted/canceled asynchronous operation may use an existing Task as backing. Do not add pooling or an IValueTaskSource-style subsystem yet.
  • ValueTask<T> Result & GC Completion: Add typed inline results plus Task-backed asynchronous results. Managed-reference T must remain correct across GC. Completion, faults, and cancellation must follow the same observable semantics as Task without turning ValueTask into a hidden managed object.
  • Async ValueTask Return Integration: Allow async ValueTask and async ValueTask<T> methods. I would prioritize correctness and reuse the existing state-machine/completion machinery; I would not introduce clever pooling or a second async builder system just to advertise zero allocations. Completed/manual ValueTasks are already useful; deeper allocation optimization can come in a later performance block once the semantics are locked.
  • Awaiter/ValueTask GC, Threads, Exceptions & Async-Iteration Integration: Cross-system milestone: custom awaiters and ValueTask through worker threads, forced GC, cancellation, exceptions, try/catch/finally, library boundaries, nested Task/ValueTask awaits, and async iterators. Awaiter state and managed references must survive suspension correctly and cleanup must remain deterministic.
  • Generalized Awaitables & ValueTask Integration Audit: Final strict audit: custom class/struct/generic/extension awaiters, Task compatibility, YieldAwaitable, ValueTask/ValueTask<T>, async ValueTask methods, GC/lifetime, exceptions/cancellation, generated C, diagnostics, and the complete cumulative make test.
Completed

Native Heap & Function Pointer Interop

▾
  • Native Heap Runtime Foundation: Add one platform-neutral runtime allocation layer for unmanaged allocation/free with checked sizes and deterministic failure behavior. Keep it completely separate from the managed GC.
  • NativeMemory Allocation Surface: Expose explicit unsafe allocation/free APIs through the standard library. Raw native allocations remain manually owned; no hidden GC ownership or fake safety.
  • Generic Typed Native Allocation Completion: Build typed allocation on the existing where T : unmanaged proof: checked count * sizeof(T), typed pointers, unmanaged structs, generic callers, zero-length behavior, and overflow diagnostics/runtime checks. No second unmanaged classifier.
  • Native Reallocation & Alignment Completion: Add realloc/aligned allocation semantics through the same runtime backend, including preservation/failure rules, alignment validation, zero-size behavior, and strict C portability.
  • Native Function Pointer Type Foundation: Introduce a real native function-pointer type with parser/semantic/type-system support. It should be unmanaged, nullable, comparable, storable in unmanaged structs, and restricted to ABI-compatible parameter/return types.
  • Native Function Address & Indirect Call Completion: Support obtaining addresses of compatible native extern functions and invoking them indirectly. Calls must reuse the existing native-boundary GC-safe transition instead of creating a second call path.
  • Native Function Pointer ABI Integration: Allow function pointers as native extern parameters and return values, including function tables supplied by C libraries. Preserve the existing platform C ABI initially rather than prematurely inventing a calling-convention matrix.
  • Generic Function Pointer & Unmanaged Storage Integration: Compose function pointers with where T : unmanaged, pointers, stackalloc, native heap allocation, structs, arrays/tables, Span views, and native function-table patterns without special-case generic lowering.
  • Native Heap, Function Pointers, GC, Threads & Exception Boundary Integration: Exercise allocated native buffers and function tables through managed threads, GC, native calls, callbacks, cleanup paths, exceptions, and library boundaries. Verify native memory never becomes a GC object and native indirect calls obey the same runtime transition rules as ordinary extern calls.
  • Native Heap & Function Pointer Integration Audit: Full block audit covering allocation/reallocation/free, alignment, generic unmanaged storage, Span/native-buffer composition, indirect calls, ABI tables, threads/GC/exceptions, generated-C strictness, diagnostics, and the complete cumulative make test.
Completed

Unmanaged Generics, Pinning & Native Buffer Interop

▾
  • Unmanaged Generic Constraint Foundation: Add where T : unmanaged with one authoritative recursive unmanaged-type classification. Primitive/native value types, enums, pointers, and structs composed entirely of unmanaged fields qualify; managed references and structs containing them do not. Integrate it with generic types, methods, inference, specialization, diagnostics, and existing constraint handling. I think this belongs first because otherwise later generic native-buffer APIs would need type-name hacks or compiler exceptions.
  • Generic Pointer & Unmanaged Stack Storage Completion: Allow unsafe generic code constrained by unmanaged to use T*, pointer arithmetic where valid, sizeof(T), and stackalloc T[count]. Reuse the existing pointer/stackalloc implementation rather than building a generic-only path. This gives us a clean foundation for native Span<T> construction.
  • Managed Pinning Runtime Foundation: Add the internal GC/runtime pin contract. A pin keeps its managed owner rooted and records that its address must remain stable. VOID's collector is currently non-moving, so this does not need a new collector design, but establishing a real pin contract now prevents us from baking “the GC never moves” into the language ABI forever. It also prepares the runtime for a future moving/compacting collector without changing source semantics.
  • fixed Statement & Scoped Pointer Semantics: Add fixed syntax and lowering through the existing scope/control-flow cleanup machinery. Pin acquisition/release must survive normal exit, return, break, continue, and exceptions. The fixed pointer is scoped and cannot be captured or returned as though its managed backing were permanently pinned. Existing explicitly unsafe raw-pointer behavior remains available; fixed becomes the correct lifetime-aware managed/native bridge.
  • Structural Pinnable Reference Protocol: Make fixed structural rather than teaching the compiler a growing list of special types. A receiver exposing the proper pinnable-reference contract can participate, with receiver evaluation exactly once. This is the same architectural idea that worked well for the earlier Index/Range consumers and ref foreach.
  • Array, Span & Memory Pinning Completion: Wire managed arrays, Span<T>, ReadOnlySpan<T>, Memory<T>, and ReadOnlyMemory<T> into that one pinning model. Writable sources expose writable pointers where legal; readonly views remain readonly. Range/slice-produced views must retain the correct owner and offset. GC, null/empty cases, nested slices, and evaluation-once behavior all get focused coverage.
  • Unmanaged Span<T> / ReadOnlySpan<T> Construction: Add unsafe pointer+length construction for unmanaged storage. Once created, native-backed spans should use the same indexing, Range, slicing, ref foreach, CopyTo, Fill, and Clear machinery as managed/stack spans. No parallel “NativeSpan” type. Crucially, I would not make Memory<T> pointer-backed here: Memory<T> is heap-storable and therefore needs an ownership model for arbitrary native memory. Keeping Memory managed-array-backed remains the cleaner contract.
  • Native Buffer Call Integration: Prove the intended native workflow end-to-end: managed storage → fixed → pointer + length → existing unsafe extern calls, plus unmanaged Span views around externally owned buffers. Cover ref/out/in, callbacks, library output/import, generic unmanaged helpers, slices, and evaluation-once semantics. I would keep native APIs explicit as pointer+length here rather than inventing a magical direct Span ABI.
  • Pinning, GC, Threads, Exceptions & Native Boundary Integration: Stress nested pins, forced GC, ThreadPool/managed threads, native callbacks, exceptions/finally, library boundaries, generic buffers, managed owners, and cleanup. Verify pins cannot accidentally keep objects pinned forever and cannot disappear while native code still legitimately uses the scoped pointer. High-iteration race/stress variants remain opt-in outside make test, consistent with the existing harness policy.
  • Unmanaged Memory & Native Buffer Integration Audit: Final block audit across unmanaged constraints → generic stackalloc → pointers → fixed/pinning → arrays/Memory → Span/Range/ref → native calls/callbacks → GC/threads/exceptions. This gets the mandatory focused audit and full cumulative make test, exactly like the previous integration audit.

Index, Range & Contiguous Memory Integration

▾
  • Index & From-End Foundation: Real Index value type; prefix ^; ^0, ^1, normalization and diagnostics. Preserve binary XOR.
  • Range Syntax & Value Foundation: Real Range value type; .., a..b, ..b, a.., .., ^ endpoints; normalization APIs.
  • General Index/Range Consumer Semantics: reusable protocol around Length, existing integer indexing, Slice(int,int); side effects once; no type-name special casing.
  • Arrays & Span Index/Range Completion: array[^1], Span/ReadOnlySpan from-end indexing and ranges. Array ranges allocate copies; Span ranges return views; readonly remains readonly.
  • Managed Array-Backed Memory<T> Foundation: heap-storable Memory<T>/ReadOnlyMemory<T> using only T[] + start + length. No native backing yet.
  • Memory Slicing, Conversion & Span Bridge: Array→Memory, Memory→ReadOnlyMemory, slicing, Length, IsEmpty, .Span; no implicit Memory→Span conversion.
  • Memory Suspension & GC Integration: Async, iterators, async iterators, Tasks, ThreadPool, continuations, GC, managed-reference elements; prove lifetime safety without implying thread safety.
  • Span Enumeration & Ref Foreach Completion: normal Span foreach, foreach(ref T...), foreach(ref readonly T...), readonly/escape/capture/async restrictions.
  • Contiguous Memory Operations Completion: CopyTo, TryCopyTo, Fill, Clear; overlap-safe copy; tiny internal overlap/storage primitive permitted if necessary.
  • Index, Range & Contiguous Memory Integration Audit: cross-feature audit and authoritative full make test: Memory→Span→Range→ref, stackalloc→range→ref foreach, await/GC, readonly paths, generics, exceptions, evaluation-once behavior.

By-Reference Semantics & Span Foundations

▾
  • First-class ref locals: Add ref T local aliases over locals, parameters, fields, and array elements. The compiler tracks lvalue provenance, definite assignment, and the managed owner that must stay rooted when a ref points inside an object or array.
  • Ref assignment & aliasing: Complete target = ref source, chained aliases, mutation through aliases, struct-field refs, readonly checks, and control-flow lifetime while reusing VOID's existing write-target and by-reference argument machinery.
  • Ref returns: Add ref T method returns, return ref, and ref-returning calls as writable targets while rejecting references to dead locals, temporaries, and stack storage that cannot outlive the call.
  • Ref-returning properties & indexers: Extend the same by-reference semantics through properties and indexers with single evaluation, generic specialization, valid interface or virtual dispatch, readonly rules, and managed-owner retention.
  • ref readonly & escape scopes: Add readonly references plus formal escape-scope analysis for stack storage, parameters, managed interior references, and longer-lived storage. Introduce an explicit scoped surface only if the language needs it to express those rules clearly.
  • Ref struct foundation: Add stack-only ref struct values that may contain byrefs without silently escaping into the managed heap. Fields, constructors, methods, properties, and ordinary stack locals follow the same lifetime model.
  • Ref-like lifetime & suspension safety: Integrate ref-like values with generics, closures, delegates, exceptions, iterators, async methods, await, and yield. Unsafe capture or suspension paths are rejected unless the compiler can prove the lifetime is valid.
  • Span<T> & ReadOnlySpan<T>: Build spans as ordinary standard-library ref structs over the by-reference foundation, with length, indexed access, writable versus readonly behavior, and deliberate rules for native and managed element storage.
  • Span integration & ref foreach: Connect spans to arrays, stackalloc, valid unsafe pointer-backed views, slicing, managed-owner lifetime, and ref/ref readonly foreach so safe byrefs and the existing native-memory model meet cleanly.
  • By-reference & span integration audit: Audit refs, escape scopes, ref structs, spans, arrays, stack storage, generics, interfaces, native calls, closures, exceptions, GC, and diagnostics together. The block closes architectural gaps without pulling in unrelated ownership, SIMD, scheduler, or memory abstractions.

Block-wide invariant

Text positions are Unicode scalar positions. Bytes stay explicit.

Normal string operations use VOID's 32-bit char and count Unicode scalar values. Length, indexing, ranges, search positions, and enumeration therefore describe characters in that scalar model, while ByteLength exposes the underlying UTF-8 byte count.

This phase does not claim grapheme-cluster, locale, culture, case-folding, or normalization semantics. Those are separate text concerns and should not be smuggled into the core string contract.
