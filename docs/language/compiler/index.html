voidc

One compiler pipeline.
Builds and tooling share it.

VOID source is parsed, specialized/lowered, semantically analyzed, lowered to C, and compiled natively. The same front end now powers voidc check and persistent semantic tooling queries without duplicating language rules.

Compiler architecture

Language intelligence stays in voidc.

voidc makes each language decision once. Parsing and semantic analysis decide what the program means; lowering, native output, voidc check, and editor queries consume those same decisions. That keeps builds and tooling from drifting into separate implementations.

Object model lowering

Construction, dispatch, interface contracts, events, delegates, and generic constraints all reach code generation through the same semantic bindings. Later stages consume those decisions instead of rebuilding the object model.

Receivers & generic calls

Value receivers and type receivers now share normal member-binding rules instead of treating a type name like a runtime value. Ordinary, qualified, built-in, and constructed-generic types can resolve static values, methods, method groups, and generic calls through the same overload, accessibility, specialization, and code-generation machinery.

Value types, arrays & control flow

Value layouts keep their semantics as they move through arrays, closures, iterators, nullable storage, and GC-traced state. The compiler does not switch to a separate representation just because a value crosses one of those boundaries.

Pattern analysis & switch lowering

Declaration/property/recursive patterns reuse normal type relationships, property access, conversions, definite assignment, and GC-safe temporaries. Pattern switches, guards, and switch expressions share that matcher and preserve deterministic first-match ordering.

Inference & extension binding

Generic method inference and extension methods flow through the normal overload resolver and monomorphizer instead of a separate call path. Ordinary instance members keep precedence.

Advanced interface lowering

Static interface contracts, constrained static calls, and default interface methods extend the existing interface model and specialize to concrete calls/dispatch where appropriate.

Threading, timed waits, cancellation & GC

Generated workers enter the same managed runtime model as the main thread. GC coordination, blocking states, cancellation wakeups, structured lock cleanup, and atomics are lowered through VOID-owned runtime calls instead of exposing OS threading details to user code.

Nullability & initialization

Nullable value storage, lifted operations, named/default arguments, instance/object/array/collection initializers, target-typed collection expressions, static members, and deterministic type initialization lower through the same semantic model.

voidc check

Runs the complete compiler front end and diagnostics, then deliberately stops before C generation, output creation, or native compilation.

Semantic query sessions

A persistent analyzed project can answer symbol, type, definition, member, and callable-parameter questions through the public compiler query API.

Structured diagnostics

Compiler diagnostics carry severity, stable code, message, source snapshot/span, and ordered note/help context. Text excerpts and optional JSON are rendered from that same record, while generic-specialization failures preserve their original source provenance.

Debug/source mapping

Debug C output emits standard #line directives. GCC/Clang then place original VOID filenames and lines in normal native debug information.

voidc lsp

The compiler hosts the LSP lifecycle and document state, publishes live diagnostics, serves hover/signature help and semantic completion, resolves definitions/references/symbols, and analyzes every open project document from one synchronized in-memory snapshot.

Operator binding & generic provenance

Unary/binary operators, static-interface operator contracts, and constrained generic dispatch are bound semantically before lowering. Iterator promotion preserves generic origin/constraint metadata so valid generic operations remain valid after suspension.

Conversion binding & generic provenance

Standard/user-defined conversions, nullable lifting, target-typed sites, static-interface conversion contracts, and constrained generic implicit/explicit dispatch now bind through one semantic engine. Iterator and closure lowering preserve the conversion proof instead of reclassifying specialized concrete types later.

Native ABI

Unsafe declarations, pointers, ABI structs, callbacks including ref/out/in callback parameters, exported library entry points, memory primitives, and native dependencies lower directly through the C boundary.

Executable & library output

The same project/compiler pipeline can emit native executables or static archives. [Export] methods seed reachability and gain stable C wrappers while internal VOID implementations stay private.

One compiler model

Builds, diagnostics, and editor features reuse normal compiler semantics.

The compiler owns the source spans and semantic facts behind each error, then presents that information through terminal text, optional JSON, checking, and editor diagnostics instead of maintaining separate error engines. voidc lsp still keeps unsaved project state synchronized and asks the same resolver used by real builds for types, calls, definitions, and diagnostics; richer note/help transport through LSP remains a separate layer rather than a new semantic path.

Type-qualified access

A type name is now a real receiver.

Ordinary, qualified, constructed-generic, and built-in types resolve static fields, constants, properties, methods, method groups, and generic calls through one semantic path. Built-in parsing and generic default surfaces use source-owned StandardLibrary members instead of primitive-specific compiler switches.

Source to runtime

The compiler now preserves more of the path back to VOID source.

Inline typed and inferred out declarations reuse the ordinary overload, generic inference, scope, flow, diagnostics, and tooling systems. At runtime, generated synchronous call paths retain truthful VOID frame information so exceptions and internal runtime failures can show the immediate source context before the full stack without confusing native or unavailable-source boundaries.
